# NeetCode 150 — pattern-wise builder

One run builds **one pattern** completely. Target: `$ARGUMENTS` — a pattern (`Trees/BFS`, `dynamic knapsack`) or a problem name (builds its whole pattern).

All paths below are relative to the repo root. `PP=<skills-root>/neetcode-pattern/scripts/pattern_plan.py`.

## Layout (fixed — names come from the CSV, never invent them)

```
neetcode_150/
├── README.md                          generated by `PP index` — never edit by hand
└── <Type>/<NN_Pattern>/               e.g. Trees/03_BFS_Level_Order/
    ├── README.md                      the pattern explained (markdown)
    ├── <nn_pattern>_lesson.html       interactive pattern lesson (e.g. 03_bfs_level_order_lesson.html)
    ├── <file>.ipynb                   one per problem, `file` column of the CSV
    └── <file>.html                    interactive step-through of that notebook
```

No `_explained.md` per problem: the notebook's markdown cells carry the explanation. To move a problem to a different pattern, edit `references/neetcode150_patterns.csv`, move its files, re-run `PP index`, and tell the user.

## Workflow

### 1. Plan
`python3 $PP plan "<query>"`. It prints the target folder and, for every file, `exists`, `COPY from blind_75/...`, or `NEW via <skill>`. If the query is ambiguous it lists the candidates and exits 2: ask the user once (AskUserQuestion) which one.

A DSA type (e.g. `Trees`) matches all its patterns. If the user wants the whole type, run `copy` for each pattern, then hand steps 2–6 to one Agent per pattern, in parallel. Each agent writes only inside its own pattern folder and skips the screenshot pass (they would share one browser). Then do step 7 and the visual pass yourself. A type can be wider than NeetCode's category of the same name: `Trees` also holds the Trie pattern (NeetCode "Tries"). When the user counts problems, check the `neetcode_category` column.

Tell the user the folder and the counts (copied / new) before writing.

### 2. Copy what blind_75 already has
`python3 $PP copy "<query>"`. It copies each `COPY` notebook and HTML into the pattern folder (dropping the `N. ` filename prefix), sets the notebook header to `**Topic:** <Type> · **Pattern:** [<name>](README.md)`, and re-points the HTML's `index.html` / `patterns.html` links to the pattern lesson. It never touches `blind_75/`.

Then, for each copied notebook:
- Check the cell order against the `leetcode-notebook` spec (see CLAUDE.md "Problem notebook cell order"). Add any missing section rather than rewriting the notebook.
- Make `## 🧩 Patterns Learned` name this pattern and link `README.md`.
- Re-run it (command in CLAUDE.md → Python). It must exit 0.

### 3. Generate the missing notebooks
For each `NEW via leetcode-notebook` line, follow the `leetcode-notebook` skill with:
- target folder = this pattern folder;
- filename = the `file` value from the plan, not a slug of the title;
- LeetCode URL from the plan (the CSV has corrected slugs; the source spreadsheet has a few wrong ones).

The optimal approach must be this pattern's template applied to the problem, so the pattern page and the notebooks teach the same thing. Run each notebook; exit 0 required.

LeetCode Premium problems (Encode and Decode Strings, Walls and Gates, Meeting Rooms, Meeting Rooms II, Graph Valid Tree, Number of Connected Components, Alien Dictionary): write the statement and examples yourself. Mark the header `(LeetCode Premium — free on neetcode.io)`.

With 3 or more new notebooks, you may run one Agent per problem with these instructions. Then run every notebook yourself before going on.

### 4. Generate the missing problem pages
For each `NEW via leetcode-visualizer` line, follow `leetcode-visualizer` with the **notebook path** as input: single-notebook mode. Don't create `patterns.html` / `index.html` in the pattern folder; the pattern lesson is the hub. Point the page's back link at `<nn_pattern>_lesson.html`.

### 5. Write the pattern `README.md`
Source material:
- The plan output's `signal` lines.
- The repo's own NeetCode notes: `python3 $PP docs <scratchpad>/ncdocs`, then grep:
  - `archetypes.txt` for the NeetCode category heading (e.g. `Trees — BFS`) — the template code;
  - `red_herrings.txt` for `<Category> · Traps` and the problem names.
- The notebooks you just built. Claim nothing the notebooks don't show.

Sections, in order:
1. `# <Pattern name>`, one line on what it is, then `**Type:** <Type> · **Problems:** N · [Interactive lesson](<nn_pattern>_lesson.html)`.
2. `## The tell`: the words or shapes in a problem statement that signal this pattern.
3. `## The idea`: plain words plus one small ASCII diagram.
4. `## Template`: a commented Python skeleton, the same one the notebooks' optimal approaches use.
5. `## Problems`: a table with the columns `# | Problem | Difficulty | Twist on the template | Time | Space | Notebook | Interactive`. Use relative links, in CSV order (easy → hard).
6. `## Traps and look-alikes`: the patterns this gets confused with, and how to tell them apart.
7. `## Say it in the interview`: 2–3 sentences to say out loud.

### 6. Build the pattern lesson
Follow `dsa-interactive-lesson` with **concept = this pattern**, written to `<nn_pattern>_lesson.html` in the pattern folder. Map its 13 sections like this:
- **Hero / canonical example:** the pattern's first problem in the CSV.
- **"What is <pattern>?":** the README's tell and idea.
- **Method 1:** the template traced on the canonical problem. The code is the notebook's optimal solution, synced line by line.
- **Method 2:** a second problem's variant of the template, or the brute force it replaces.
- **Practice questions:** the pattern's other problems, as `<details>` with a hint and a link to each problem's `.html`.
- **Edge cases, mistakes, interview:** from the traps section.

It must pass `python3 <skills-root>/dsa-interactive-lesson/scripts/check_lesson.py <file>`. Do the screenshot pass if a browser tool is available.

### 7. Index and verify
- `python3 $PP index` regenerates `neetcode_150/README.md`: the build counts, plus links for every file that now exists.
- Run the case-sensitive link check from `dsa-index-updater` step 4 on:
  - the pattern `README.md`;
  - the lesson;
  - each problem `.html`;
  - `neetcode_150/README.md`.

  Fix every `MISSING`.
- `python3 $PP plan "<query>"` must now show `exists` on every line.
- Report:
  - the files created, and which were copied and which generated;
  - the notebook run results;
  - the `check_lesson.py` result;
  - whether the visual pass ran.

  Do not commit.

## Overview
`python3 $PP list` prints every type and pattern with its status: `done`, or how many problems and pattern pages exist.
